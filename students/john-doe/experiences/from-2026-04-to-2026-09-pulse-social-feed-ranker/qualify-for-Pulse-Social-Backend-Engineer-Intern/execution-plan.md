# Gap Fill Plan for the Pulse Backend Engineer Intern Role

> This is the abbreviated version of the 08 teaching example. In the real workflow, part two of `qualify-execution-plan` produces a roughly 350-line full version including a POC priority matrix, tutorial directory index, and 12-week timeline. Here we keep just the POC trunk and timeline skeleton. For the full version, see the Cedar Ridge [execution-plan.md](../../../from-2025-06-to-2025-09-CedarRidge-maternity-bi-agent/qualify-for-Cascadia-Health-Insights-AI-Solutions-Engineer/execution-plan.md).

## 1. Execution Principles and Timeline

Plan window: 2026-02-01 to 2026-04-30, 12 weeks total, 12 to 15 hours per week, roughly 144 to 180 hours total. Aligns with the mid to late May 2026 Pulse referral interview window (take-home submission plus on-site).

The 3 Core gaps go to "I can explain it clearly in interview plus a working demo." The 3 Important gaps go to "concept clear plus 200 lines of sample code." Production-grade is not required.

## 3. Key POC Summaries

Each POC is essentially a small project for learning a skill, not a fake business project. No corporate context required. Use a public dataset like NYC open data or a Wikipedia corpus as raw material. The full version has 5 to 10 detailed bullets per POC.

- **POC-01 Go production**: Use Go to rewrite the Cedar Ridge SQL reporting project as a CLI, with the full production hygiene kit (tests, lint, CI, cobra).
- **POC-02 gRPC**: Add a gRPC server to POC-01 exposing a query interface, with a simple Go client for testing.
- **POC-03 K8s + Helm**: Use a Helm chart to deploy POC-02 to minikube. Learn the pod, service, and ingress concepts.
- **POC-04 Redis**: Add a "last N queries" cache layer to POC-02 using Redis sorted sets.
- **POC-05 Microservice boundary**: Split POC-02 into query-service and index-service, calling each other via gRPC.
- **POC-06 Observability**: Add OpenTelemetry, Prometheus, and structured logging (zap) across every POC.

## 5. 12-Week Timeline Skeleton

- **Week 1 to 4 (POC-01)**: Go syntax + standard library + one real CLI project. Weekly cadence: 3 hours each on Monday, Wednesday, and Friday, plus a 5 to 6 hour block on the weekend.
- **Week 5 to 6 (POC-02)**: Integrate gRPC + Protobuf into POC-01.
- **Week 7 to 8 (POC-03)**: Deploy POC-02 on minikube and learn how to write a Helm chart.
- **Week 9 (POC-04 + POC-05 in parallel)**: Add Redis cache to POC-02 and split it into two services.
- **Week 10 (POC-06)**: Add an observability layer across every POC.
- **Week 11 to 12 (interview prep)**: Run a take-home simulation using all POCs. 2 to 3 mock interview rounds (via the `qualify-mock-interview` skill) to surface weak spots and fix them.

## 6. Failure and Mitigation

- **Risk**: Go's learning curve is steeper than expected (Go's interface, goroutine, and channel habits differ a lot from Python). POC-01 may overrun. **Mitigation**: At the end of Week 4, run an honest assessment. If POC-01 is not "demo-ready," drop POC-06 entirely and move its budget to POC-01.
- **Risk**: minikube runs poorly on John's 8GB MacBook, blocking hands-on K8s practice. **Mitigation**: Apply for the UW CS department's free GCP credits and use a real cluster.
- **Risk**: Self-study has no reviewer, so the Go code ends up non-idiomatic. **Mitigation**: After each POC, drop the code into the Pulse internship cover letter, ask a familiar engineer to look it over, or do a code review pass via `qualify-coach`.
