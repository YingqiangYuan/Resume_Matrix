# 02 — Runbook for `learn_build_resume_matrix`

This project is **a curriculum + an agent-skill library**, not a runtime application. There is no server to start, no test suite to execute, no build artifact to produce. The "run" of this project is **reading the lessons + invoking the skills in Claude Code against your own resume**. This runbook captures the parts that *do* have commands: environment setup, how to invoke each skill, and where artifacts land.

## Prerequisites

| Tool | Version | Install command |
| :--- | :------ | :-------------- |
| `mise` | latest | `curl https://mise.run \| sh` then add `eval "$(mise activate zsh)"` (or `bash`) to your shell rc |
| `uv` | latest | Managed by `mise` — no separate install needed |
| Python | 3.12 | Managed by `mise` — no separate install needed |
| Claude Code | latest | Per Anthropic's install docs for Claude Code (macOS / Windows / VS Code / JetBrains / `claude.ai/code`) |

After installing `mise`, `cd` into the repo root and `mise install` once to pick up the versions declared in `mise.toml`.

## First-time setup

```bash
# 1) Clone (if you haven't)
git clone <repo url>
cd learn_build_resume_matrix-project

# 2) Pick up tool versions from mise.toml
mise install

# 3) Create the virtualenv
mise run venv-create

# 4) Install the (currently empty) dependency set — task exists for forward compatibility
mise run inst
```

After step 4, `.venv/` exists at the repo root and `pyproject.toml`'s package is installed in editable mode. Nothing else needs to be running.

## Day-to-day commands

| Goal | Command |
| :--- | :------ |
| Recreate the virtualenv from scratch | `mise run venv-remove && mise run venv-create` |
| Re-install after editing `pyproject.toml` | `mise run inst` |
| Activate the venv manually | `source .venv/bin/activate` |
| Browse the curriculum | Open `examples/README.md` and walk lessons 01 → 13 in order |
| Browse the worked example | Open `students/john-doe/README.md` |
| Invoke an agent skill | In Claude Code: `/<skill-name>` (e.g. `/qualify-gap-analyze`) — see "Running locally" below for the full skill catalog |

The repo defines no Make targets, no shell aliases, no test runners.

## Running locally — invoking each first-class skill

All skills live under `.claude/skills/` and are invocable from Claude Code with `/<skill-name>`. The recommended invocation order follows the 6-stage qualify pipeline (Lessons 07 / 08) and then the resume-output skills (Lessons 09 / 10).

### Stage 1 — Diagnose

```
/qualify-gap-analyze
```
- **Inputs the skill will ask for:** path to your master resume, path to the target JD (or paste the JD text), optionally landscape docs.
- **Output:** `gap-analysis-cn.md` (or `.md`) written under the relevant `students/<you>/experiences/<exp>/qualify-for-<company>-<role>/` folder. Open it and read the verdict + per-gap deep-dives.
- **Next:** if the verdict is `proceed`, hand the gap analysis to mini-project-design.

### Stage 2 — Design the case

```
/mini-project-design
```
- **Inputs:** the gap analysis from stage 1, the JD, and (for elevate mode) an existing thin case; or (for from-scratch mode) the JD plus a chosen execution venue.
- **Output:** `case-cn.md` in the same `qualify-for-...` folder.
- **Then run the review loop:** in a **separate terminal** run `/mini-project-review` against the same case folder. It writes `review-NN.md`. Hand that back to `/mini-project-design` (still the design terminal), which writes `fix-NN.md` and revises `case-cn.md`. Iterate until verdict = `approve`.

### Stage 3 — Plan execution

```
/qualify-execution-plan
```
- **Inputs:** gap-analysis + approved case + JD.
- **Output:** `execution-plan-cn.md` (main plan) + `pocs/poc-NN-<slug>/README-cn.md` per gap + `tutorials/NN-<slug>-cn.md` stubs in the same `qualify-for-...` folder.

### Stage 4 — Learn the gaps

```
/qualify-coach
```
- **Inputs:** the execution plan + POC scaffolds (and optionally the case / gap-analysis / landscape).
- **Output:** `coach-notes/concept-<slug>.md` per concept; running `coach-notes/_progress-cn.md`.
- **Pace:** one concept per session is normal. Don't try to drain the gap list in one sitting — the coach is dialogue-driven and only advances when you acknowledge each concept.

### Stage 5 — Stress test

```
/qualify-mock-interview
```
- **Inputs:** JD + case (mandatory); execution-plan and coach-notes (optional but recommended).
- **Critical:** invoke this in a **fresh Claude Code conversation** — not in the same context where you ran qualify-coach. The coach has memory of your struggles and would soften the interview. The mock interview must be a clean room.
- **Output:** `mock-interview-{round}.md` with transcript + debrief (verdict, "go back to coach" list, suggested next-round timing).
- **Loop:** after debrief, return to qualify-coach for the items in the "go back to coach" list. Re-run mock-interview when those items are closed. Stop when verdict is `ready`.

### Stage 6 — Compress to resume

For each Bullet Set (one per Job Family angle per experience):

```
/bullet-writer
```
- **Inputs:** master resume path + case path + target Job Family angle (e.g., "AI Engineer", "Data Analyst").
- **Output:** edits the master resume — appends a new `### Bullet Set N, <Company>, <Project> (<angle> emphasis)` section under the relevant Experience + inline rationale blockquote.

Then, optionally, for JD-specific tailoring:

```
/bullet-reviewer
```
- **Inputs:** master resume path + Bullet Set pointer (number or description) + target JD.
- **Output:** suggestions in chat first, then on your approval edits the master — Mode A (in-place tweak) or Mode B (append a JD-targeted variant Bullet Set).

For each Summary Variant (one per Job Family direction):

```
/summary-writer
```
- **Inputs:** master resume path + target Job Family direction + the Bullet Sets that belong to that direction (the summary is reverse-engineered from them, so they must exist first).
- **Output:** edits the master — appends `### Variant <letter>, for <Job Family> roles` under the Summary section + rationale blockquote.

Then optionally:

```
/summary-reviewer
```
- Same shape as `bullet-reviewer` but operating on a Summary Variant.

## Common failures and fixes

The repo has none documented yet. As issues come up, append entries here in the format:

> **Symptom:** what you saw.
> **Cause:** what was actually wrong.
> **Fix:** what resolved it.

Likely first entries (anticipated, not yet observed):

> **Symptom:** `mise install` fails on Python 3.12.
> **Cause:** Some macOS setups need Xcode CLI tools for Python builds.
> **Fix:** `xcode-select --install`, then re-run `mise install`.

> **Symptom:** Skills don't appear in Claude Code's `/` menu.
> **Cause:** Claude Code looks for skills under `.claude/skills/` relative to the current working directory; opening the project from a parent folder hides them.
> **Fix:** Open Claude Code from the repo root (`cd learn_build_resume_matrix-project && claude .`).

> **Symptom:** `qualify-coach` and `qualify-mock-interview` give weirdly soft interview verdicts.
> **Cause:** They were run in the same Claude Code conversation, so the mock-interview inherited coaching sympathy.
> **Fix:** Always run mock-interview in a fresh conversation (new terminal / new chat).

## Where to look when something breaks

| Surface | Where to look |
| :------ | :------------ |
| Skill not being picked up | `.claude/skills/<skill-name>/SKILL.md` — check `name:` matches the slash invocation, `description:` is non-empty |
| Skill misbehaves mid-run | Inspect its `references/` for the rules it's supposed to enforce, and the `templates/` for boilerplate it substitutes into |
| Output file in the wrong place | All first-class skills write into the **current `students/<name>/experiences/<exp>/qualify-for-<company>-<role>/`** working directory by convention. If files land at the repo root, you invoked from the wrong cwd. |
| Master resume edits look duplicated | `bullet-reviewer` Mode B appends a new variant rather than editing in place — confirm Mode A was the intended choice |
| Curriculum link broken | The README at `examples/README.md` is the canonical index; lesson cross-references live inside each lesson's README |

There are no log files. There are no dashboards. The "system" is your filesystem after each skill writes its outputs.
