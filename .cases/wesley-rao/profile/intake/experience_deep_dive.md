# Experience Deep Dive / 经历深度记录

## 经历 1：行业研究与量化研究助理 @ 青岚投资

### 背景与上下文
- 青岚投资是一家 base 深圳的投资公司，管理资金规模约 3 亿元人民币。
- 所在团队主要负责对不同投资项目进行初步研究，包括查阅资料、整理信息、形成行业报告，并向领导汇报研究结论。
- 这段经历发生在本科大二阶段，当时希望尽早接触金融相关工作，因此进入公司参与行业研究。
- 在进入公司后，量化研究方向是后续新开设的，你因为本身就对量化方向感兴趣，主动申请进入量化组学习和参与支持工作。

### 角色与日常
- 在行业研究方向，日常工作主要包括：查资料、做笔记、撰写文章、准备汇报演讲材料。
- 后来成为组长后，职责进一步扩展到团队管理与项目协调，包括：给组员分配任务、帮助组员解决困难、与领导同步工作进度、组织会议、跟进组员执行进展，以及参与部分面试工作。
- 在量化研究方向，前期主要通过查阅论文、整理因子来熟悉研究框架；后期开始使用 Python 对港股科技板块的数据进行清洗和整理，为量化研究提供基础数据支持。
- 你对自己在量化部分的评价比较客观：已经接触到了研究流程和基础支持工作，但参与深度还不算很深。

### 技术与工具
- **编程/处理工具**：Python，Excel
- **数据来源/平台**：同花顺数据库
- **方法与任务类型**：资料检索、行业资料整理、因子整理、论文查阅、港股科技板块数据清洗与整理

### 个人贡献与成果
- 在行业研究团队中，你的核心贡献首先是把本职工作稳定完成，没有在执行层面出现明显失误，保证了研究支持工作的连续性。
- 成为组长后，你承担了团队运营和协同责任。你的主要管理方式是：每周主动和组员沟通项目进展及问题、及时回应组员提出的困难、与领导沟通整体进度，并通过会议和跟进机制推动任务往前走。
- 在量化组中，你最大的实际贡献是从零开始承接数据整理任务。在自己此前没有系统学过相关内容的情况下，通过不断向 AI 询问、边学边做，完成了港股科技板块数据的清洗和整理工作，为后续研究提供了可用的数据支持。

### 反思与收获
- 这段经历中最大的挑战来自量化组的数据整理工作，因为你当时并没有系统学过这部分内容。
- 你采取的方式是高频请教 AI，并结合实际任务边学边做，把原本陌生的工作逐步推进下去。
- 对你来说，想做 quant 并不是实习后才产生的念头，而是在实习开始之前就已经有的兴趣；这段经历更像是一次现实接触，让你对 quant 相关工作有了更具体的理解。
- 你后来把目标更多落在 QD（Quantitative Developer）上，是因为你判断自己更擅长这个方向，也认为这条路径对未来能力积累和创业会更有帮助；相比之下，QR 对数学要求更强，而你并不认为自己最突出的优势在纯数学上。

### 💡 评价
这段经历里一个很明显的亮点是：你不是只停留在“对量化感兴趣”，而是主动从行研支持转去新开的量化组，哪怕一开始并不熟，也愿意边学边做把事情接起来。这个“主动靠近目标方向”的动作，在面试里会比单纯说自己感兴趣更有说服力。

另一个很实在的亮点，是你不仅做执行，还承担过带组、推进进度、向上汇报的责任。对于本科阶段的经历来说，这说明你已经不只是一个被动接任务的人，而是有一定 owner 意识和团队协调能力的人。

最后，你对自己适合 QD 而不是 QR 的判断也很成熟——这说明你不是在盲目追热门，而是在结合自己的能力结构、兴趣和长期目标做选择。这种自我认知，在后续求职叙事里会非常重要。

## 经历 2：银行交易处理系统（C++）

### 背景与上下文
- 这是数据结构与算法课程中的个人项目。
- 由你独立完成，整体开发周期大约一周。
- 项目目标是构建一个交易处理系统：读取输入后完成合法性验证，根据时间规则处理交易顺序和交易逻辑（包括手续费计算），并在交易完成后支持长时间、大规模信息查询。

### 角色与日常
- 由于是个人项目，你独立负责了系统的完整设计与实现。
- 整个系统的大致流程包括：读取输入 → 验证交易合法性 → 根据时间规则决定执行顺序 → 完成交易逻辑与手续费计算 → 支持后续查询。
- 查询侧需要支持四类主要模式：收入查询、客户信息查询、历史交易查询、当天所有交易查询。
- 项目的核心难点不在单一模块，而在于：系统不是“先读完所有输入再统一执行”，而是要在持续读取过程中，只要条件满足就立刻触发执行，因此执行顺序和规则处理需要非常严谨。

### 技术与工具
- **语言**：C++
- **核心数据结构**：hash table，priority queue
- **算法/思路**：binary search，大规模数据快速查询，动态执行逻辑，边读取边验证并触发执行
- **设计重点**：在保证规则正确性的前提下，兼顾高频查询与较大规模数据场景下的性能表现。

### 个人贡献与成果
- 你独立完成了整个系统的设计与实现，尤其负责交易读取、合法性校验、执行调度、交易处理与查询支持等核心链路。
- 你最满意的模块是“边读取边验证合法性并开始执行”的部分，因为这里的逻辑最复杂：既要正确处理输入，又要在读取过程中按照条件即时推进执行，而不是等全部输入结束后再统一处理。
- 在性能优化方面，你使用了 **binary search** 来支持大规模 query 场景下的高效查询，这说明你在写功能之外，也有意识地考虑系统在规模增大后的效率表现。
- 你遇到的大部分 bug 集中在读取与执行环节，主要与执行顺序和规则边界有关；虽然你没有逐一记住所有 bug 细节，但核心上是围绕“复杂规则下如何保持逻辑一致性”展开的。

### 反思与收获
- 这个项目里最难的部分，就是规则很多、逻辑顺序复杂，必须把各类条件之间的先后关系理清，否则系统就容易在执行阶段出错。
- 对你来说，这种偏规则处理、偏顺序控制、偏系统逻辑的工作是有吸引力的，也比较能体现你的优势。
- 这类项目让你更自然地靠近 QD / systems / backend 相关方向，因为它不是单纯做分析，而是在处理有约束条件的动态系统，并且要兼顾正确性和性能。

### 💡 评价
这段项目很有说服力的一点，是你不是只做了一个“静态作业”，而是在处理一个带有实时执行逻辑、顺序约束和查询压力的动态系统。面试官通常会很看重这种项目，因为它更接近真实工程里的状态机、执行引擎和系统设计问题。

另一个亮点是你对复杂逻辑的耐心和控制力。你最难的部分刚好也是最有价值的部分：规则多、顺序复杂、边界情况多，但你能把它完整实现出来，还进一步考虑 query 的性能，这会让人觉得你是有 systems sense 的。
