# 教程 06：Excel 对账与金融数据工具认知（手工基线 + Bloomberg 定位）

对应 POC-06，🟠 Nice-to-have（最低优先级）。这篇比其它教程短，但要能真正上手用。

## 这篇教程想让你达到的目标

读完并跟着做完一遍，你应该能：

1. 用 Excel 从头到尾手工复现一次对账，找出两张表里对不上的那只证券（一个 break）。
2. 讲清楚"手工做对账到底慢在哪、错在哪"，并且诚实地给出一个手工 vs 工具的量级对照（不吹成"省了 3 小时"这种没根据的数字）。
3. 知道 Bloomberg 终端是什么、金融机构拿它干嘛、为什么你现在一般拿不到、面试被问到时怎么诚实回答。

一句话动机：你已经有一个 PostgreSQL 对账项目，用 SQL 自动找 break。但面试官（尤其是 Virtu 这种做 Trading Ops 的）会想知道"你懂不懂这活儿手工是怎么干的"。因为只有亲手用 Excel 慢慢对过一遍，你才有资格说"我用 SQL 把它自动化了、快在哪、省了什么"。Excel 就是那个"手工"的一端，SQL 是"工具"的一端。这篇教程帮你把"手工"这一端亲手跑一遍。

## 先搞清楚：对账到底在对什么

对账（reconciliation，业内口语叫 recon）说白了就是：**同一件事，两个地方各记了一笔账，我们核对它们是否一致，不一致的地方就叫 break（差异 / 断点）。**

在 Trading Ops 的场景里，最常见的一种是"持仓对账"：

- **内部账（our books）**：券商 / 基金自己的系统记录"我这个账户现在持有多少股某证券"。
- **托管行账（custodian）**：帮你保管证券的第三方银行（custodian bank，比如道富、纽约梅隆）记录"我这边替这个账户保管着多少股"。

正常情况下这两个数应该一模一样。如果某天某只证券，内部记的是 1000 股、托管行记的是 900 股，那就有一个 break，Ops 的人得去查：是漏记了一笔交易？是交割（settlement）还没到账？还是哪边录错了？

> 💡 小技巧：面试时如果你能自然说出"break"这个词，并且能举一个具体例子（比如"某只股票内部记 1000、托管行记 900，差 100 股"），会显得你真的懂这行，而不是只会背概念。

## 我们要贯穿全程的小例子

我准备了两张很小的表，全程用它们。你可以自己在 Excel 里手敲进去，边敲边跟着做。

**表 A：内部持仓表（Internal Positions）**，放在一个叫 `Internal` 的工作表（sheet）里：

| 账户 Account | 证券代码 Ticker | 数量 Quantity |
|---|---|---|
| ACCT001 | AAPL | 1000 |
| ACCT001 | MSFT | 500 |
| ACCT001 | TSLA | 300 |
| ACCT002 | AAPL | 800 |
| ACCT002 | NVDA | 1200 |

**表 B：托管行持仓表（Custodian Positions）**，放在一个叫 `Custodian` 的工作表里：

| 账户 Account | 证券代码 Ticker | 数量 Quantity |
|---|---|---|
| ACCT001 | AAPL | 1000 |
| ACCT001 | MSFT | 500 |
| ACCT001 | TSLA | 300 |
| ACCT002 | AAPL | 800 |
| ACCT002 | NVDA | 1150 |

眼尖的你可能已经看出来了：`ACCT002` 的 `NVDA`，内部记 1200 股，托管行记 1150 股，差 50 股。这就是我们要用 Excel"一步步找出来"的那个 break。

先剧透答案是好事，这样后面每一步你都知道"应该指向哪里"，学起来更踏实。真实工作里表有几千上万行，你肉眼是看不出来的，才需要下面这些招式。

> ⚠️ 常见坑：证券代码在两张表里必须写法一致。`AAPL` 和 `aapl`、`AAPL `（末尾有个空格）、`AAPL.O`（带交易所后缀）在 Excel 眼里是三个不同的东西，会导致本来能对上的行被判成对不上。这是新手对账最常踩的坑，后面单独讲怎么防。

## 招式一：VLOOKUP / XLOOKUP，把两张表按代码对起来

对账的第一步，是把散在两张表里的同一只证券"拉到同一行"来比。这就是 VLOOKUP / XLOOKUP 干的事：**拿 A 表里的一个 key（这里是证券代码），去 B 表里找出对应的那个值（数量），搬过来。**

### 先说 VLOOKUP（老函数，哪台电脑都有）

我们在 `Internal` 表里加一列，叫"托管行数量"，让它自动去 `Custodian` 表里把对应证券的数量抓过来。

不过这里有个前提坑：这个例子里证券代码不是唯一的（`AAPL` 在 ACCT001 和 ACCT002 各出现一次）。VLOOKUP 只会返回它找到的**第一个**匹配，所以直接用 Ticker 做 key 会对错行。为了让例子干净，我们先做一个"账户+代码"的联合 key。

**步骤：**

1. 在 `Internal` 表最左边插入一列（假设现在数据在 B、C、D 列，Account 在 B、Ticker 在 C、Quantity 在 D）。在新的 A 列，第 2 行输入：

   ```
   =B2&"|"&C2
   ```

   这会把账户和代码用一个竖线拼起来，比如 `ACCT002|NVDA`。往下拖，每行都生成一个唯一 key。

2. 在 `Custodian` 表也照做一遍，同样在最左边生成 `账户|代码` 的联合 key。

3. 回到 `Internal` 表，在数量列右边找个空列（假设是 F 列），第 2 行输入：

   ```
   =VLOOKUP(A2, Custodian!$A:$D, 4, FALSE)
   ```

   逐个拆解这个公式在说什么：
   - `A2`：我要拿这一行的联合 key 去找。
   - `Custodian!$A:$D`：去 `Custodian` 表的 A 到 D 列这个范围里找。`$` 是把范围钉死，往下拖公式时范围不会跑偏。
   - `4`：找到匹配的那一行后，返回这个范围里**第 4 列**的值（A 是第 1 列，数量 Quantity 在 D 列，正好是第 4 列）。
   - `FALSE`：要求"精确匹配"。这个一定要写 FALSE，写 TRUE 是模糊匹配，对账里用 TRUE 是灾难。

4. 往下拖到最后一行。现在 `Internal` 表里，每只证券旁边都多了一列"托管行那边记的数量"。

拖完后，你的 `Internal` 表大概长这样（只看关键几列）：

```
联合Key              内部数量   托管行数量(VLOOKUP抓来的)
ACCT001|AAPL         1000       1000
ACCT001|MSFT         500        500
ACCT001|TSLA         300        300
ACCT002|AAPL         800        800
ACCT002|NVDA         1200       1150      ← 这两个数不一样！
```

到这一步，两张表已经"对齐"了，差异也已经浮出来了，只是还没自动标出来。

> ⚠️ 常见坑：VLOOKUP 的第三个参数是"列号"，不是"列字母"。而且它只能往右找，key 列必须在返回值列的左边。很多人被这个规则坑到，这也是为什么下面的 XLOOKUP 更好用。

### 再说 XLOOKUP（新函数，更好用，2021 之后的 Excel / Microsoft 365 才有）

XLOOKUP 是 VLOOKUP 的升级版，不用数"第几列"，也不要求 key 在左边。同样一件事，用 XLOOKUP 写：

```
=XLOOKUP(A2, Custodian!$A:$A, Custodian!$D:$D, "未找到")
```

拆解：
- `A2`：要找的 key。
- `Custodian!$A:$A`：在托管行表的 A 列（联合 key 列）里找。
- `Custodian!$D:$D`：找到后，返回同一行 D 列（数量）的值。
- `"未找到"`：如果压根没找到，就显示"未找到"，而不是报一个丑陋的 `#N/A` 错误。

> 💡 小技巧：`"未找到"` 这个第四参数其实很重要。对账里"找不到对应记录"本身就是一种 break（比如内部有这只证券，托管行那边完全没有），能让它显示成人话，比一堆 `#N/A` 好排查多了。

如果你的 Excel 有 XLOOKUP，优先用它；没有就用 VLOOKUP，两者在这篇里效果一样。

## 招式二：两列相减找差异 + IF 判断

对齐之后，找差异就是小学减法。在 `Internal` 表再加一列"差异 Difference"：

```
=D2-F2
```

（D 是内部数量，F 是刚抓过来的托管行数量。）

结果会是：

```
证券           内部    托管行   差异
ACCT001|AAPL   1000    1000     0
ACCT001|MSFT   500     500      0
ACCT001|TSLA   300     300      0
ACCT002|AAPL   800     800      0
ACCT002|NVDA   1200    1150     50    ← 非零！这就是 break
```

差异是 0 的行都对得上，非 0 的行就是 break。我们这张小表一眼能看到那个 `50`，但真实的表有几千行，`50` 会淹没在一片 `0` 里，你需要一个"自动喊出来"的办法。

用 IF 加一列"状态"，让 Excel 替你判断：

```
=IF(G2=0, "OK", "BREAK")
```

（G 是差异列。）意思是：差异为 0 就写"OK"，否则写"BREAK"。这样你可以直接对"状态"列做筛选（Filter），只看 BREAK 的行。

> 💡 小技巧：真实数据里数量可能有小数（比如债券、基金份额），两个数在计算机里可能差 0.0000001 却不该算 break。这时别用 `=IF(G2=0,...)`，改成 `=IF(ABS(G2)<0.01, "OK", "BREAK")`，给一个容差。`ABS` 是取绝对值，因为差异可能是正也可能是负。

## 招式三：条件格式，把差异自动标红

上面的"BREAK"是文字。如果你想让对不上的行**自动变红**，一眼扫过去就看见，用条件格式（Conditional Formatting）。

**步骤：**

1. 选中"差异"那一列的数据区域（比如 G2 到 G6）。
2. 菜单：开始 → 条件格式 → 新建规则。
3. 选"使用公式确定要设置格式的单元格"。
4. 公式框里输入：

   ```
   =$G2<>0
   ```

   `<>` 是"不等于"。意思是"只要这个格子里的差异不等于 0，就套用下面的格式"。`$G2` 里 `$` 钉住 G 列、行号不钉，是为了让规则能逐行判断。

5. 点"格式"，把填充色设成红色，确定。

现在那行 `NVDA` 的差异格子会自动变红。以后数据一变，红色会自动跟着变，不用你手动重刷。

> ⚠️ 常见坑：条件格式的公式里，`$` 的位置很讲究。想"整行变红"要写 `=$G2<>0`（只钉列）；如果写成 `=$G$2<>0`（列行都钉死），那所有格子都只会去看 G2 那一个格子，规则就废了。这个坑非常常见，记不住就先只标单个格子，够用。

## 招式四：SUMIF，按账户/证券做小计核对

有时候你不想逐笔对，只想先看"每个账户的总持仓数量对不对得上"，快速定位是哪个账户出了问题。SUMIF 就是"按条件求和"。

比如想算 `Internal` 表里 `ACCT002` 的总数量：

```
=SUMIF(Internal!B:B, "ACCT002", Internal!D:D)
```

拆解：
- `Internal!B:B`：去账户列里找。
- `"ACCT002"`：找等于 ACCT002 的那些行。
- `Internal!D:D`：把这些行对应的数量列加起来。

对 `Custodian` 表也算一遍 `ACCT002` 的总数量，两个总数一减，如果不为 0，说明这个账户里藏着 break，再深入去逐笔查。这是一种"先粗筛账户、再细查证券"的分层思路，真实工作里很实用。

> 💡 小技巧：SUMIF 只能带一个条件。如果要"账户 = ACCT002 且证券 = NVDA"这种多条件求和，用 SUMIFS（多一个 S），可以叠加好几个条件。

## 招式五：数据透视表（PivotTable），做每账户汇总

数据透视表是 Excel 里最能唬住外行、其实很简单的功能。它的作用是：**把一大堆明细行，按你指定的维度自动分组汇总**，几秒钟出一张汇总表。做账户级的持仓总览特别快。

**步骤（以 `Internal` 表为例）：**

1. 选中整张明细表（连表头一起选）。
2. 菜单：插入 → 数据透视表 → 确定（放到新工作表）。
3. 右边会出现一个字段列表。把 `Account` 拖到"行"区域，把 `Quantity` 拖到"值"区域。
4. Excel 立刻生成：

   ```
   账户       数量总和
   ACCT001    1800
   ACCT002    2000
   总计        3800
   ```

对 `Custodian` 表做一样的透视表，你会得到 `ACCT002` 是 `1950`（因为 NVDA 少了 50）。两张透视表一比，`ACCT002` 对不上，方向就锁定了。

> 💡 小技巧：数据透视表最爽的地方是"改了明细不会自动更新，右键 → 刷新一下就更新"。面试里如果被问"你会数据透视表吗"，能说出"我用它做过账户级的持仓汇总来定位差异"就非常加分，比空说"会"强得多。

> ⚠️ 常见坑：透视表要求源数据是"干净的表格"，也就是每列有表头、没有合并单元格、没有空行插在中间。数据不干净时透视表会分组混乱或直接报错。做透视表前先确认数据规整。

## 到这里，你已经手工对完一次账了

回顾一下你刚才走的完整流程：

1. 两张表各建一个"账户|代码"联合 key（防对错行）。
2. 用 VLOOKUP / XLOOKUP 把托管行数量抓到内部表旁边（对齐）。
3. 两列相减求差异。
4. 用 IF 打上 OK / BREAK 标签，或用条件格式标红。
5. （可选）用 SUMIF / 数据透视表先做账户级粗筛。
6. 筛出 BREAK 行，得到结论：`ACCT002` 的 `NVDA` 差 50 股。

这就是一次完整的手工对账。恭喜，你现在有资格谈"手工基线"了。

## 关键一节：为什么 Excel 手工做对账很痛

这一节是整篇最重要的，因为它直接支撑你项目叙事里"我为什么要用 SQL 自动化"这句话。请认真读。

手工 Excel 对账的痛点，具体有这么几个：

**1. 只能抽查，很难真正全量。**
表几千上万行时，就算你用了 VLOOKUP + 条件格式，你也倾向于"扫一眼红的、大概看看"。人一累就会跳行、漏看。真正的全量核对，人是扛不住的。

**2. 极易出错，而且错得悄无声息。**
联合 key 拼错一个字符、VLOOKUP 范围少选一行、复制公式时忘了拖到底、代码带了个隐形空格，任何一个小失误都会让某些 break 被漏掉或误报，而且你往往不知道自己错了。对账最怕的就是"看起来对上了，其实漏了"。

**3. 不能规模化，是一次性劳动。**
你今天辛辛苦苦搭好的这套 Excel，明天数据一换，很多步骤要重来：重新粘数据、重新拖公式、重新检查范围。它不是一个"系统"，是一次性手工活。

**4. 每天重来，且无法留痕。**
持仓对账是每天要做的事（T+1，每个交易日结束后对前一天）。手工意味着每天重复同样的机械劳动，而且很难留下"今天查了什么、哪些 break、怎么处理的"这种可追溯记录。审计和复盘都很难。

**这四点自然引出一句话：所以要用 SQL / 工具把它自动化。**

你的 PostgreSQL 项目正好解决了上面每一条：SQL 的 `FULL OUTER JOIN` 一次比对**全量**（不是抽查）；写好的查询**可重复运行、结果稳定**（不会因为手滑出错）；每天只要跑一遍同一个脚本（不用重搭）；结果可以落库、留痕、可审计。这就是"工具"相对"手工"的价值。

### 诚实地记一次手工计时（这点面试很重要）

面试官会警惕"我用工具省了 3 小时"这种张口就来的数字。你要做的是**诚实地、有方法地**给一个量级对照，而不是编一个精确数字。

推荐做法（非正式计时，n=3）：

- 用你上面这个小例子，或者造一张几百行的假数据，**手工**完整对一遍，用手机掐表记时间。重复 3 次（第一次生疏、后两次熟练），取个大概范围。这就是 n=3 的非正式计时，样本很小，只够说"量级"。
- 再用你的 SQL 脚本对同一份数据跑一遍，记时间。
- 对照时**只说量级、加限定词**。比如：

  > "在我造的一份约 500 行的数据上做了 3 次非正式计时：手工 Excel 对账大概要 15 到 20 分钟，而且我不完全信任自己没漏行；SQL 脚本跑完是秒级，且是全量比对。这只是小样本的粗略对照，但量级上工具明显更快、更可靠。"

注意这段话里的诚实信号：**"约 500 行""3 次非正式计时""大概""不完全信任自己""秒级""小样本""量级上"**。这些限定词不是让你显得不自信，恰恰相反，它们让面试官相信你是个严谨、不吹牛的人。Trading Ops 这行最看重的就是"这人报的数我能信"。

> ⚠️ 常见坑：千万别说"我用 SQL 自动化后每天节省 3 小时"这种没有测量支撑的话。面试官只要追一句"你怎么算出来 3 小时的？"你就露馅了。宁可说"我只做了小样本的粗略计时，量级上是分钟对秒"，也不要编一个听起来很厉害但站不住的数字。

## Bloomberg 终端是什么（简短科普 + 面试怎么处理）

这一节帮你建立基本认知就够了，你现在拿不到终端，也不需要真的会用。知道"它是什么、能干嘛"，面试时不露怯即可。

**Bloomberg 终端（Bloomberg Terminal）是什么？**
它是彭博公司卖的一套金融数据 + 交易 + 通讯的专业软件，界面是标志性的黑底加橙 / 琥珀色文字，配一个专用键盘。金融机构的交易员、分析师几乎人手一台。

**金融机构拿它干嘛？**
- 看**实时行情**：股票、债券、外汇、大宗商品的实时价格。
- 查**证券参考数据**：某只证券的代码、发行信息、公司基本面等（这跟你做对账相关，对账时经常要核对证券的标准标识）。
- 发消息 / 聊天：业内很多人用 Bloomberg 内置的聊天工具（IB / Instant Bloomberg）谈交易、对信息，它几乎是华尔街的"微信"。
- 做分析、跑函数、拉历史数据等等。

对 Trading Ops 来说，Bloomberg 常用来**查证券的参考数据、核对标识、看某笔交易涉及证券的信息**，是辅助对账和查 break 的一个信息来源。

**为什么你现在一般拿不到？**
一个 Bloomberg 终端订阅一年要两万多美元，是给在职员工配的专业工具。学生基本接触不到（少数商学院有几台共享终端，Data Science 专业通常没有）。所以"没上手过 Bloomberg"对你这个背景是完全正常的，面试官也清楚。

**面试怎么诚实处理？**
被问到"你用过 Bloomberg 吗"，标准的诚实回答是：

> "我没有实际上手用过 Bloomberg 终端，因为学生一般拿不到订阅。但我知道它是什么：金融机构用来看实时行情、查证券参考数据、以及业内通讯的专业平台。在对账的语境下，我理解它常被用来核对证券的标准标识和参考数据。我上手很快，真到岗位上有终端我能很快学会。"

这个回答的结构是：**诚实承认没用过 → 证明你知道它是什么和干嘛用 → 表达学习意愿**。不装懂、不心虚，反而显得成熟。

> 💡 小技巧：绝对不要假装用过 Bloomberg。面试官很可能天天用它，随口一个具体功能（"那你一般用哪个 function 拉这个数据？"）就能戳穿。诚实说"没用过但知道是什么"永远是安全且加分的。

### 顺带一句：这类岗位的技能优先级

给你一个清晰的排序，帮你分配精力：

- **Excel + SQL 是这类 Trading Ops 岗位的必需项**（must-have）。这是你天天要用的活儿，也是这篇教程和你 SQL 项目重点打磨的地方。招聘 JD 里几乎一定会写。
- **Bloomberg 是加分项**（nice-to-have）。会当然好，但因为是在职才配的工具，面试官不会指望一个应届生已经精通。你"知道它是什么"就够了，别本末倒置去花大力气啃一个你摸不到的工具。

所以你的精力分配应该是：把 SQL 对账项目和 Excel 手工基线做扎实（这是你的核心竞争力），Bloomberg 花十分钟读懂本节、能诚实聊两句即可。
