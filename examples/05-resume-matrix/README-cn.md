# 1 加 N 大法：一份母版简历，N 份投递版本

> 这是 examples 系列里的第五篇。前四篇我们讲了招聘流程、ATS、应届生和有经验者的简历该怎么写。这一篇换一个角度：当你要同时投递好几个不同方向的岗位时，怎么用一份素材高效产出 N 份针对性的简历。

## 1. 课程导读

到目前为止，你已经知道了简历应该给谁看，知道了 ATS 是怎么回事，知道了应届生和有经验者各自的简历该怎么写。这些是单份简历的能力。

这一节我们要解决的是另一个问题：现实里，大多数人投简历不会只盯一个方向。一个 CS 应届生可能同时投 Software Engineer、Data Engineer、Machine Learning Engineer 三个 Job Family。一个有几年经验的人可能同时投初创公司和大公司，行业上又横跨医疗、金融、互联网。每个方向需要展示的重点都不一样，每家公司在意的故事线也不一样。

如果你给每个方向、每家公司都从零写一份简历，时间成本会爆炸。如果你只用一份简历投所有岗位，针对性会很差。这一节讲一种中间路线，叫 1 加 N 大法。它的本质是用一份「母版」管所有素材，再用「删减」生成针对每个方向的投递版本。

这一节没有实操，先把概念和操作流程讲清楚，之后的 examples 会教你怎么用 AI 工具高效维护这套素材。

> 注：这一节里我们用了一个虚构的学生 John Doe 当例子，不是真人。他的项目、公司名都是为了帮你理解操作过程而编出来的。

---

## 2. 简历的本质：高信息密度的精修

我们先回到一个基本问题：简历到底是干什么用的？

简历是把你最漂亮的羽毛，用极高的信息密度，集中展示给招聘的人看的一份文档。Recruiter 给你的时间通常是几秒钟，Hiring Manager 多一点也就是几十秒。一页纸里要讲完你是谁、做过什么、能解决他什么问题。

「高信息密度」意味着每一行字都要承担工作。如果一条 bullet 对当前这个岗位没有帮助，它占的就是别的 bullet 本来可以占的位置。一条对 SDE 岗位很有用的 bullet（强调系统架构、API 设计），对 Data Engineer 岗位的价值会低很多；反过来，一条强调 ETL Pipeline 设计的 bullet，对 SDE 岗位的吸引力也有限。

所以你的经历可以很多，可以讲的故事很多，但是针对某一个具体的岗位，你只会用到这些素材的一部分。你也很可能要用一种完全不一样的 presentation 方式，调整侧重点，去给对的人看对的东西。这就是大家常说的「精修简历」。

精修说起来容易。问题在于，精修说起来容易，做起来时间成本可不低。一份认真精修的简历，从读 JD、挑素材、改 bullet 措辞、调整顺序、对齐排版，搞下来可能要一两个小时。如果你同时在投 10 个岗位、横跨 3 个方向，每个都从头精修，你一周时间全花在改简历上了。

那有没有一种做法，既能针对性强、又能效率拉满呢？必须有邪修。这就是 1 加 N 大法。

---

## 3. 1 加 N 大法是什么

简单一句话概括：维护 1 份信息齐全的母版简历，从它派生出 N 份针对不同岗位的投递版本，派生的过程只做删减、不做新增。

母版简历是什么？是一份「巨长」的简历。它把你的全部素材都堆在一起，按时间顺序或者按项目对应的岗位方向整理排序。Skills 部分是你会的所有技能的大合集。最关键的是 Summary：你不只写一个，而是把每个你想投的方向都单独写一份针对性的 Summary，全部塞在简历开头。

派生简历是什么？它就是把母版打开，删掉跟这个岗位不相关的 Summary、删掉不需要的 Skills 行、删掉对这个方向没帮助的经历或者 bullet。剩下的就是这个方向的投递版本。

这个母版我们根本不会拿去投递。它的作用是「素材库」，外加一个固定的排版模版。所有的投递版本都是从它身上做减法做出来的。

为什么这个做法效率高？因为做减法比做加法容易得多。加法意味着你每改一份简历，要重新想：这个岗位重点是什么，我哪段经历可以用，怎么写措辞，怎么调顺序。减法只需要看着已经写好的素材，问一句「这条对这个岗位有用吗」，没用就删。

> 注：这里说的「删减」不只是删 bullet，也包括删 Skills 里跟岗位无关的整行、删某个不相关的 Summary 变体、把某段经历的「数据重点版」换成「AI 重点版」（其实也是删，删掉了 AI 版那一段）。本质上，所有操作都是「保留」和「删除」，没有「新写」。

## 4. 一个具体的例子：三个项目，五段 bullet，四份简历

抽象的概念讲完了，我们看个具体的人怎么操作。

> 注：之所以拿医疗、金融来举例，是因为这两个行业是 AI 在业务里落地最好、岗位和钱最多的两个方向。

John Doe 是华盛顿大学 CS 硕士在读，目标 2026 年 12 月毕业。他做过三段实习，分别在医疗 AI 创业公司、金融衍生品经纪商、消费社交产品。他的项目都是 AI、Data、Software 三种能力的不同组合。

第一段实习是 2025 年夏天的医疗项目。完整的案例描述在 [from-2025-06-to-2025-09-clinical-notes-summarization-platform-cn.md](../../students/john-doe/experiences/from-2025-06-to-2025-09-clinical-notes-summarization-platform-cn.md)。这段经历里他既用了 LLM 做临床病历摘要，也搭了 FHIR 数据的 ETL Pipeline，还设计了 PostgreSQL 的 Schema。你可以从 AI 角度讲他这段经历，重点放在 Prompt 工程、评估 Harness、RAG；也可以从 Data 角度讲，重点放在 ETL Pipeline、Schema 设计、PHI 去标识化。

第二段是 2025 年冬天的金融项目。案例在 [from-2025-12-to-2026-01-realtime-fraud-detection-pipeline-cn.md](../../students/john-doe/experiences/from-2025-12-to-2026-01-realtime-fraud-detection-pipeline-cn.md)。这段同样可以两面写：AI 角度强调 XGBoost 模型训练、PSI 漂移监控；Data 角度强调 Kafka 流式 Pipeline、exactly-once 语义、Snowflake feature store。

第三段是 2026 年夏天的社交产品项目。案例在 [from-2026-06-to-2026-09-feed-ranking-microservice-cn.md](../../students/john-doe/experiences/from-2026-06-to-2026-09-feed-ranking-microservice-cn.md)。这段相对纯粹，就是软件开发：Go 写微服务、gRPC、Kubernetes、灰度上线。这段没有第二种重点写法。

所以 John Doe 的母版简历里会出现五段大经历，每段下面 3 到 4 条 bullet：

1. 医疗项目，AI 重点版本
2. 医疗项目，Data 重点版本
3. 金融项目，AI 重点版本
4. 金融项目，Data 重点版本
5. 社交项目，软件开发重点版本

注意第 1、2 段和第 3、4 段其实是同一个项目的两种写法。母版里会重复出现，因为这是他在做投递时的「素材池」，不需要简洁。

Summary 同样维护三份，分别对应三个目标方向：AI Engineer、Data Engineer、Software Engineer。Skills 是一个全集，覆盖他会的所有技术。

母版长这样：[resume.md](../../students/john-doe/resume.md)。打开看一眼你就明白「巨长」是什么意思了。

## 5. 怎么从母版导出针对岗位的简历

John Doe 可以同时投 AI、Data、Software 三类岗位。他会从同一份母版派生出几份针对性简历，过程全是删减。

投 AI Engineer 岗位的时候，他保留 Summary 变体 A，保留 AI/ML 相关的 Skills 行，保留 bullet set #1（医疗 AI 版）、#3（金融 AI 版）、#5（社交软件版，因为软件能力对 AI 岗位也是加分项）。删掉其它的。结果就是 [resume-role-1.md](../../students/john-doe/resume-role-1.md)。

投 Data Engineer 岗位的时候，他保留 Summary 变体 B，保留 Data 相关的 Skills 行，保留 bullet set #2（医疗 Data 版）、#4（金融 Data 版）、#5。结果是 [resume-role-2.md](../../students/john-doe/resume-role-2.md)。

投 Software Engineer 岗位、目标公司是一家医疗公司的时候，他保留 Summary 变体 C，保留软件/后端相关的 Skills，保留 bullet set #1（医疗 AI 版，因为目标公司在意医疗 AI 这个领域）和 #5。结果是 [resume-role-3.md](../../students/john-doe/resume-role-3.md)。

投 Software Engineer 岗位、目标公司是一家金融公司的时候，他保留 Summary 变体 C，同样的软件 Skills，但保留 bullet set #3（金融 AI 版）和 #5。结果是 [resume-role-4.md](../../students/john-doe/resume-role-4.md)。

看出门道了吗？四份针对性简历，每一份都是从同一份母版上「删」出来的。措辞、数字、排版完全继承母版。他不需要重写任何一个 bullet，不需要重新想任何一个数字，不需要担心说法前后不一致。这就是这个做法的杠杆。

## 6. 看一个完整的样例

为了让你直观感受这个做法落地以后什么样，我们把 John Doe 的完整资料都放出来了。你不需要现在就照着改自己的简历，后续的 examples 会教你怎么用 AI 工具高效维护这套结构。

母版简历：

- [resume.md](../../students/john-doe/resume.md)：包含 3 份 Summary 变体、全集 Skills、5 段 bullet set 的母版简历。

派生出来的 4 份投递简历：

- [resume-role-1.md](../../students/john-doe/resume-role-1.md)：AI Engineer 方向。
- [resume-role-2.md](../../students/john-doe/resume-role-2.md)：Data Engineer 方向。
- [resume-role-3.md](../../students/john-doe/resume-role-3.md)：Software Engineer 方向，目标公司是医疗行业。

每段经历背后的原始素材，叫 case 文件，里面是项目的完整叙述（背景、做了什么、产出、技术栈）。这是写 bullet 的源头，bullet 是从这里提取压缩出来的：

- [医疗 AI 项目案例](../../students/john-doe/experiences/from-2025-06-to-2025-09-clinical-notes-summarization-platform-cn.md)

建议的看法：先把三份 case 文件读一遍，理解项目本身是什么；再打开母版 [resume.md](../../students/john-doe/resume.md)，对照看每个 bullet set 是怎么从 case 文件里抽出来的，注意同一个项目的两种重点写法（AI 版 vs Data 版）措辞上的差别；最后打开四份派生简历，对照母版看哪些内容被保留、哪些被删掉。

## 7. 核心洞察

回过头来看，1 加 N 大法之所以成立，是因为简历这个东西有几个隐藏的特性。

第一，针对性 = 删减，不是新写。一份针对性强的简历，本质上是从一个更大的素材池里挑出最相关的子集。挑选这个动作的成本远低于创作。

第二，同一段经历可以有多个「框」。同一个项目，从 AI 角度讲是一个故事，从 Data 角度讲是另一个故事。这两种讲法都不是假的，只是侧重不同。你需要的是提前把两种讲法都写出来，而不是临到投递再现编。

第三，Summary 和 Skills 是「定位标签」，bullet 是「证据」。一份简历对一个岗位的契合度，先看 Summary 是不是说到了对方在意的话，再看 Skills 是不是命中关键词，最后才看 bullet 提供的证据。所以三者都需要按岗位维护多份。

第四，母版是不投出去的，但它是最值钱的资产。母版的完整度直接决定了你能投多少方向、多快产出简历。维护好母版，比写好任何一份单独的投递简历都重要。

## 8. 导师寄语

我见过太多求职者，在每个岗位前都要从头打开 Word 文档重写一遍简历。两天后投了五份岗位，每份简历都有点不对劲，有的还把上一份简历的公司名忘记改。这种工作流既累，质量又不稳定。

1 加 N 大法的逻辑很朴素：把工作集中在一处做完，剩下的都是机械的复制和删减。它把「写简历」这件事拆成了两层。第一层是底层素材的维护，频率低、深度高，写一次能用很久。第二层是面向某个具体岗位的派生，频率高、深度浅，每次几分钟。

这个结构最大的好处不是省时间，而是让你能在保持高质量的前提下做大量投递。同样是投 30 份简历，从同一份母版派生的 30 份在内容质量上会比你每次从头写的 30 份高得多，因为你每次精修的成本都被摊薄到了那一份母版上。

后续的 examples 我们会讲怎么用 AI 工具维护母版里的每一块（写 Summary、写 bullet、深化项目素材），以及怎么把派生的过程自动化。到那时你会发现，1 加 N 这个结构和 AI 工具是天作之合：AI 最擅长的就是基于已有素材做有约束的删减和改写，而不是凭空创作。
